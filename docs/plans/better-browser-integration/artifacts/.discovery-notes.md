# Implementation Discovery Notes

## Technology stack

- Desktop client: C++23, Qt 6 Widgets, CMake 3.22+, Conan/vcpkg/submodules, GoogleTest.
- Browser integration: JavaScript/HTML/CSS Chrome WebExtensions Manifest V3 extension, Node 22 validation tests, native messaging to the desktop executable.
- Primary commands: `npm test` for the extension; CMake with `-DBUILD_TESTS=On` followed by `ctest --output-on-failure` for native tests.

- `chatterino-extension/background.js`: native-port lifecycle, desired attachments, tab/window routing, readiness acknowledgements, integration health.
- `chatterino-extension/overlay.js`: Twitch chat measurement and current destructive replacement behavior.
- `chatterino-extension/anti-wipe.js` and `styles.css`: restoration and hiding of Twitch's React-owned chat subtree.
- `chatterino-extension/content.js`, `activity-state.js`, `voting-ui.js`, `notification-ui.js`: browser-native Twitch controls, activity state, interactive handoff, and UI adapters.
- `chatterino-extension/twitch-api.js`: Twitch GraphQL observation and channel-points interaction fallback.
- `chatterino-extension/protocol.js`: JavaScript protocol versioning and partial validation.
- `chatterino-extension/integration-health.js`, `popup.js`, `popup.html`: health reporting and operator-visible recovery state.
- `src/BrowserExtension.cpp`: native-host process, browser HWND capture, and host/GUI IPC forwarding.
- `src/singletons/NativeMessaging.cpp` and `NativeMessagingProtocol.cpp`: desktop message dispatch, protocol validation, attachment status, engagement/pin/reward updates.
- `src/widgets/AttachedWindow.cpp`: Windows ownership, geometry, Z-order, fullscreen, drag, maximize, and target lifetime.
- `src/widgets/splits/SplitInput.cpp`: reward-message handoff back through the browser.
- `chatterino-extension/tests/` and `tests/src/NativeMessaging*.cpp`: unit and contract coverage.
- `.github/workflows/extension-test.yml`: extension validation and packaging CI; no real browser/native E2E job exists.

## Current behavior and constraints

- The extension has protocol v1, readiness signals, request acknowledgements, retry timers, integration health, and extension-local tests.
- `portConnectBlocked` is permanent for the lifetime of the service worker once certain native-host errors occur.
- Pending attachment retries live in process-global maps and timers even though Manifest V3 workers can restart.
- Twitch chat is modified before native attachment is proven; hidden/restored DOM state can outlive a failed native overlay.
- Desktop attachment state is represented by a single Boolean even though `AttachedWindow` stores multiple window records.
- Reward chat routing selects a tab by channel name, which is ambiguous when the same channel is open in multiple windows.
- The HWND regression test inspects source text rather than executing the native boundary.
- The current working tree contains substantial user changes. Planning and implementation must preserve and first checkpoint those changes.
